# 遥测

使用指标能帮你理解用户如何使用你的程序,以及把精力放在哪。但和网站不同,命令行用户期望掌控自己的环境,程序在背后悄悄做事会让他们吃惊。

## 未经同意不要回传数据

用户一定会发现,一定会愤怒。要非常明确地说明:

- 你收集什么。
- 为什么要收集。
- 如何匿名,以及如何做的匿名化。
- 保留多久。

## opt-in vs. opt-out

- opt-in 更安全。问用户是否愿意贡献数据。
- 如果默认 opt-out,在官网和首次运行时告诉用户,并提供简便的关闭方法。

## 合理实践的范例

- Angular —— opt-in 加入 Google Analytics,用于功能优先级排序。用户可更换 tracking ID 指向自己的 GA 属性。
- Homebrew —— 向 GA 发送指标,有详尽 FAQ 说明做法。
- Next.js —— 匿名使用统计,默认开启。

在模仿它们的模式之前,先详细读它们做了什么 —— “opt-out”和“opt-in”说起来容易,真正做好难。

## 替代方案

- 给 Web 文档埋点。想了解用户如何使用你的 CLI 工具,就围绕你想理解的用例建文档,然后观察这些文档随时间的访问表现。看用户在文档里搜什么。
- 给下载埋点。粗略的指标,但能告诉你用量和用户用的是什么 OS。
- 直接和用户聊。主动问人们怎么用你的工具。在文档和仓库里鼓励反馈和功能请求,并尝试从提交反馈的人那里挖出更多上下文。

(延伸阅读: *Open Source Metrics*。)
